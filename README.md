# Flowline

Ограниченный движок DAG для задач из встроенного Python-реестра. Запуски переживают
остановку воркера, поддерживают повторы, отмену и бэкфиллы на 30 дат. PostgreSQL
хранит состояние и временное владение задачами; RabbitMQ передаёт уведомления.

## Возможности и гарантии

- Неизменяемые версии графов до 50 узлов. Проверяются имена, зависимости и циклы.
- Задача доступна после успешного завершения всех зависимостей. Их результаты
  передаются следующей задаче. Ошибка после трёх попыток завершает запуск неуспешно.
- Владение выдаётся на 15 секунд с уникальным token. После истечения срока задача
  доступна другому воркеру, а прежний результат отвергается.
- Эффект задачи и её завершение фиксируются одной транзакцией. Таблица `effects`
  имеет уникальный ключ `(run_id,node)`: повторное выполнение не удваивает эффект.
- Лимит активных задач задаётся для каждого запуска; глобально допускаются четыре
  активных владения. Бэкфиллы могут занимать не более трёх: текущим задачам оставлен
  слот. При наличии обоих классов выдача чередуется.
- Несколько планировщиков создают единственный суточный запуск благодаря
  уникальности `(name,version,logical_date,kind)`. Повтор запроса бэкфилла безопасен.
- Отмена запрещает фиксацию результатов выполнявшихся задач. Готовые эффекты
  сохраняются; отмена не является компенсацией.

Стек: Python 3.11+, FastAPI, PostgreSQL 17, RabbitMQ, psycopg, Docker.
`engine.py` содержит выдачу задач, транзакции и защиту от устаревших результатов;
`scheduler.py` — суточное расписание UTC; `worker.py` — встроенный реестр;
`api.py` — управление графами и запусками.

## Запуск

```sh
docker compose up --build -d
curl -H 'X-API-Key: local-demo-key' http://localhost:8094/health
curl -X POST http://localhost:8094/definitions \
  -H 'X-API-Key: local-demo-key' -H 'Content-Type: application/json' \
  -d '{"name":"example","version":1,"parallelism":2,"daily":false,"nodes":[{"name":"seed","task":"constant","value":2},{"name":"total","task":"sum","value":3,"dependencies":["seed"]}]}'
curl -X POST http://localhost:8094/runs \
  -H 'X-API-Key: local-demo-key' -H 'Content-Type: application/json' \
  -d '{"name":"example","version":1,"logical_date":"2025-02-01"}'
```

Результат последнего узла — 5. Подставьте `<id>` из ответа:

```sh
curl -H 'X-API-Key: local-demo-key' http://localhost:8094/runs/<id>
curl -X POST -H 'X-API-Key: local-demo-key' http://localhost:8094/runs/<id>/cancel
curl -X POST http://localhost:8094/backfills \
  -H 'X-API-Key: local-demo-key' -H 'Content-Type: application/json' \
  -d '{"name":"example","version":1,"logical_date":"2025-01-01","days":30}'
```

Чтобы включить суточное расписание, зарегистрируйте новую версию с `daily:true`.
Планировщик каждые две секунды проверяет наличие запуска за текущую дату UTC.
Используется последняя версия определения; версия с `daily:false` выключает
плановые запуски этого имени. Пропущенные даты запускаются явно через бэкфилл.
Для проверки конкуренции: `docker compose up -d --scale worker=3 --scale scheduler=2`.

## Реестр задач

`constant` возвращает `value`; `sum` складывает результаты зависимостей и `value`;
`divide` делит сумму зависимостей на `value` целочисленно. Деление на ноль проходит
обычный путь повторов и ошибки. Результат ограничен типом bigint.
Параметр `delay` от 0 до 5 секунд позволяет воспроизвести остановку во время задачи.
Произвольный код, внешние HTTP-вызовы и пользовательские модули не исполняются.

## Проверки

Нужны `uv` и работающий Docker-стенд:

```sh
cp .env.example .env
set -a
. ./.env
set +a
uv sync --frozen
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
uv run python -m scripts.recovery
```

Тесты используют отдельные схемы PostgreSQL. Проверяются зависимости,
единственность эффекта, устаревший token, конкурирующие планировщики и воркеры,
лимиты, резерв текущих задач, повторы, отмена и неизменяемость определения.
Recovery создаёт 30 бэкфиллов и текущий граф, останавливает воркер через SIGKILL
во время второго узла и проверяет восстановление, результат 5 и ровно два эффекта.
Текущий граф завершается при ещё незавершённом бэкфилле; созданные сценарием
бэкфиллы затем отменяются. Запускайте recovery с одним воркером, как в исходном
Compose, и без параллельных recovery. CI повторяет тесты и аварийный сценарий.

## Ограничения

Это учебный движок ограниченных задач, без произвольного cron, часовых поясов,
динамического расширения графа и пользовательского кода. Выдача сериализована
блокировкой PostgreSQL; система ориентирована на проверяемую семантику, а не
максимальную частоту задач. Продления lease нет: задача должна уложиться в
15 секунд. Зарезервированный слот может простаивать, когда есть только бэкфиллы.

Гарантия отсутствия повторного эффекта распространяется только на встроенную
транзакционную запись в PostgreSQL. Для внешнего провайдера потребуются его
ключи идемпотентности или отдельный протокол. После ошибки графа незапущенные узлы
могут оставаться `pending`, но статус графа `failed` исключает их выдачу.
Выполнявшаяся при отмене функция может доработать локально, но результат отвергается.

Порты привязаны к localhost. Демо-ключ и пароль подходят только для локального
стенда; для внешнего использования нужны TLS и персональная авторизация.
Остановка: `docker compose down`; данные сохраняются в томе.
